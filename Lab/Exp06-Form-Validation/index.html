Client-side scripts for form validation using JavaScript

A student registration form validated entirely in the browser. The form is marked novalidate, so the browser's own bubbles stay out of the way and JavaScript decides what is wrong, says it in plain words next to the field, and tells assistive technology about it.

      How it works

      1. novalidate on the form switches off the browser's default tooltips, but the Constraint Validation API still works: every input keeps its validity object (valueMissing, typeMismatch, patternMismatch, rangeOverflow…).
      2. One validator per field (js/validate.js) reads that validity object, adds the rules HTML attributes cannot express (age, matching passwords, reserved usernames, password strength), and returns one plain-language message.
      3. setCustomValidity(message) records that message on the element, so form.checkValidity() and the :invalid state agree with the JavaScript rules.
      4. Live, but not nagging: a field is checked on blur the first time, then on every input after that. Submitting checks everything at once.
      5. Accessible errors: the field gets aria-invalid="true"; its message sits in an element named by aria-describedby; on a failed submit an error summary with links to each field takes focus (role="alert"), and focus moves to the first invalid field when a link is used.
      6. Client-side checks are a convenience, not security. Anyone can bypass them (DevTools, curl), so a real backend repeats every check on the server — the Exam 01 notes app in this repo does exactly that.
